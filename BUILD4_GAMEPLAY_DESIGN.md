# SOLO: UNICORN RUN — Build 4 Gameplay Design

## Design objective

Turn each sprint from a repeated management transaction into a compact founder
story with prioritization, uncertainty, character response, and consequences.
The simulation remains deterministic and testable; the player's decisions now
change which deterministic branch is taken.

## New sprint flow

### 1. Read the chapter state

The current sprint maps to one of four venture chapters. Chapter labels create
rhythm and establish the kind of pressure the player should expect.

### 2. Make the founder dilemma decision

A dilemma is mandatory. It applies company effects and may strengthen or damage
relationships with one or more agents. The choice remains editable until the
sprint commits.

### 3. Draft three of five opportunities

The initial three active tasks are not automatically the correct answer. The
player can replace them with either backlog task until an assignment is made.
Ignored backlog and unassigned active work both apply their listed consequences.

### 4. Assign agents

The existing role fit, intent fit, reliability, calibration, drift, trust,
workload, correlated model-family risk, hidden truth, and cached report systems
remain intact.

Agent personality is additive rather than replacing the simulation. It provides
an emotional reading of the same state:

- Aurora reacts to weak evidence, uncertainty, and rushed decisions.
- Stacks reacts to technical strain, overload, and unfinished systems.
- Brio reacts to momentum, selling opportunities, and constrained promises.

### 5. Spend Founder Attention

Founder Attention is an action economy, not just a review counter.

| Action | Attention | Additional cost | Current-result effect |
|---|---:|---|---|
| Review | 1 | Guided doctrine still pays its review Energy cost | Reveals the appropriate level of truth and creates/updates evidence |
| Approve | 0 | None | Locks the reviewed result |
| Rework | 1 | -4 Energy, -1 Runway | +12 actual quality, better evidence, smaller delayed downside |
| Ship Anyway | 0 | None | +20% immediate effects, -4 delayed Trust, -2 delayed Momentum |
| Cross-check | 1 | None | Better evidence and confidence; removes correlated-failure marker |

### 6. Commit and report

Commit applies:

- Scheduled effects from prior sprints
- Active task results
- Consequences from ignored work
- Dilemma effects
- Objective rewards when earned
- Base sprint operating cost
- Doctrine and agent-state changes
- Career ending and Founder Pass gate logic

The report explains what happened without exposing unrevealed hidden truth.

## Balance principles

- No doctrine should have a universally correct review count.
- Rework should be valuable when the current result is risky, but too expensive
  to use reflexively.
- Cross-check should be strongest against evidence gaps and correlated failures.
- Ship Anyway should be genuinely tempting in revenue or runway emergencies.
- Backlog consequences should create tradeoffs, not guaranteed punishment.
- A good run should require reading the situation, not memorizing a fixed agent
  assignment and review pattern.

## Content expansion path after Build 4

Build 4 establishes the data structures for later content without requiring a
rewrite. Future passes can add:

- More dilemmas and recurring agent story arcs
- Choice prerequisites based on relationships, evidence, or prior precedents
- Chapter-ending milestone events
- Facility-specific task pools
- More expressive character animation and actual 3D agent movement
- Spendable capital and physical garage customization
- Online company competition after the single-player balance is stable

Those are not required to validate whether the new decision loop is more fun.
